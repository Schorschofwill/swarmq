# feat: R5.5 — maschinenlesbare Agent-Spec

## Summary

Der menschenlesbare Agent-Teil von R5.5 existiert bereits als „shape-before-prose"-Markdown
(`website/reference/agent/{index,message-formats,decision-trees,error-catalog-machine}.md`).
Deferred war das **maschinenlesbare** Artefakt: strukturierte JSON-Dateien, die ein Programm
ohne Markdown-Parsing konsumieren kann. Dieses Plan liefert vier Artefakte, **aus dem Code
generiert** und per **Sync-Tests** gegen den Code verankert (kein Doku-Drift — der Grund fürs
ursprüngliche Deferral):

1. `spec/errors.json` — Error-Katalog (alle `SwarmQError`-Subklassen als Daten).
2. `spec/config.json` — alle `SwarmQConfig`-Optionen (Typ, Default, Env-Var).
3. `spec/cli.json` — alle CLI-Befehle/Flags/Defaults/Choices/Exit-Codes.
4. `spec/messages/*.schema.json` — JSON-Schema (Draft 2020-12) je Wire-Format.

Plus `spec/index.json` (Aggregat + Version) und `website/llms.txt` (Standard-LLM-Index).

## Key Technical Decisions

- **Generator als Modul `src/swarmq/agent_spec.py`**, NICHT über die lazy `__getattr__`-Surface
  exportiert (kein `import swarmq`-Overhead). Tests importieren `from swarmq.agent_spec import …`
  direkt. `python -m swarmq.agent_spec` (re)generiert alle Dateien → Konsumenten können die Spec
  für ihre installierte Version erzeugen.
- **Output unter `website/reference/agent/spec/`** → wird mit der mkdocs-Site publiziert und über
  `llms.txt` indexiert. `llms.txt` liegt im `website/`-Root (Site-Root).
- **JSON-Schema via msgspec, keine neue Dependency.** Wo ein typisierter Quell existiert
  (`SwarmQConfig`-Dataclass, `argparse`-Parser, `SwarmQError`-Hierarchie, `ScheduleDefinition`-
  Struct) wird introspektiert. Für die Inline-Dict-Wire-Formate (Task-Message, Result, Progress,
  Cancel) definiert der Generator **mirror `msgspec.Struct`s** als Schema-Quelle; `msgspec.json.schema()`
  erzeugt das JSON-Schema, und der Sync-Test decodiert **echte** emittierte Instanzen
  (`build_result_dict(...)`, echter Client-Roundtrip) per `msgspec.json.decode(real, type=Struct)` —
  ändert sich der echte Builder, schlägt der Decode fehl → Drift sichtbar.
- **Determinismus:** sortierte Keys, stabile Reihenfolge, `ensure_ascii=False`, abschließendes
  Newline. Der Master-Drift-Test regeneriert in einen tmp-Pfad und vergleicht byte-genau mit den
  committeten Dateien.
- **Version:** `importlib.metadata.version("swarmq")`; im Drift-Test wird das Versionsfeld
  ausgenommen (sonst scheitert er bei jedem Bump).

## Units (TDD — jede Unit: RED → GREEN → REFACTOR)

- **U0** Gerüst: dieses Plan-Doc, `agent_spec.py`-Skelett (`build_spec()`, `write_spec(dir)`,
  `__main__`), `spec/`-Verzeichnis.
- **U1** `errors.json`: `build_error_catalog()` — rekursive Introspektion der `SwarmQError`-
  Subklassen (name, qualname, parent, module, docstring, init-Parameter). Kuratierte Semantik
  (retriable / dlq_on_uncaught / cli_exit_code) als Mapping mit Test „jede Klasse abgedeckt".
- **U2** `config.json`: `build_config_spec()` — `dataclasses.fields(SwarmQConfig)` + Env-Var-Map.
  Test: Feld-Set == Dataclass; Env-Var-Set == `SWARMQ_*` in `__post_init__`.
- **U3** `cli.json`: `build_cli_spec()` — `_build_parser()`-Baum walken (Actions → flag/type/
  default/choices/help/required). Exit-Codes aus den bekannten Konstanten. Test: Befehls-/Arg-Set
  == Parser.
- **U4** `messages/*.schema.json`: mirror-Structs + `ScheduleDefinition`; Sync-Test decodiert
  echte Instanzen.
- **U5** `index.json` (Aggregat + Version) + `llms.txt`.
- **U6** Master-Drift-Guard-Test (regenerate-and-compare) + mkdocs-`nav`-Eintrag + Link aus
  `agent/index.md`; `mkdocs build --strict`.

## Out of Scope

- MCP-Tool-Manifest / Server (separater Konsument, falls je gebraucht).
- `mkdocstrings`-Autogen der Library-API (bleibt handgeschrieben bis API stabil).
- Änderung der bestehenden menschenlesbaren `agent/*.md` über das Verlinken hinaus.
