## Overview

Schließt die vier P2-Findings aus dem 11-Reviewer ce-review-Pass
auf `feat/r5.3-hot-reload`. Keine Verhaltensänderung aus User-Sicht —
eine Code-Hygiene-Änderung (Unit 1) und drei Test-Härtungen
(Units 2-4), die R-9 aus dem ursprünglichen R5.3-Plan voll erfüllen
(„Test-Coverage: Filter, Root-Resolution, Re-Entrancy, End-to-End").

**Nicht-Ziele:** Keine neuen Features. Keine P3-Findings aus dem
Review (separates Ticket). Keine CLI-Oberfläche.

## Problem Frame

1. **Doppelter `find_spec(args.module)` im Supervisor (Finding #7):**
   `run_multi_process_worker` ruft `_validate_module_importable`
   (ruft `find_spec`) und direkt danach `resolve_watch_dirs` (ruft
   `find_spec` erneut). `sys.modules`-Cache macht beide Calls meist
   idempotent, aber ein Modul das in seinem `__init__.py` selbst
   `importlib.invalidate_caches()` oder `sys.modules.pop(__name__)`
   aufruft (unüblich, aber valide für Plugin-Systeme) läuft sein
   Top-Level-Code **zweimal** im Supervisor. Die SEC-FINDSPEC-01-
   Risikofläche wird unnötig verbreitert.

2. **Wiring-Test prüft nur Call-Counts (Finding #8):**
   `test_run_starts_and_stops_watcher` patcht `FileWatcher` und
   assertet `fake_watcher.start.assert_called_once()` +
   `stop.assert_called_once()`. Die Konstruktor-Kwargs werden nicht
   validiert. Konkret nicht geprüft: `is_busy` ist wirklich
   `lambda: self._reload_requested`, `trigger` fire SIGHUP an
   `getpid()`, `watch_dirs` entspricht `pm._watch_dirs`. Eine
   Regression, die falsche Closure-Referenzen verdrahtet, bliebe
   unbemerkt.

3. **Kein End-to-End Test (Finding #9):**
   Die Test-Pyramide deckt isoliert ab: `FileWatcher → trigger`
   Callback (integration/test_hot_reload_e2e.py), CLI-Args →
   ProcessManager-Kwargs (test_process_manager.py::
   TestReloadRoutingThroughCLI). Die komplette Kette
   **CLI → Supervisor → Watcher → echtes SIGHUP → execvpe** ist
   nirgendwo getestet. Ein Silent-Break in dem Übergang (falscher
   Signal-Handler installiert, SIGHUP coalescing, execvpe-Pfad-
   Problem) wird erst vom Operator gefunden.

4. **Re-Entrancy-Test nur mit statischem Fake (Finding #10):**
   `TestFileWatcherLifecycle::test_trigger_suppressed_when_busy`
   setzt `is_busy=lambda: True` statisch. Das testet den Kontrakt
   des Watchers, **nicht** die echte Bindung
   `_on_reload_signal → self._reload_requested = True → is_busy`.
   Ein Refactor, der `_reload_requested` durch eine Property
   ersetzt oder die Closure-Semantik ändert, hätte keinen
   Regressions-Guard.

## Key Decisions

1. **spec als optionaler kwarg in `resolve_watch_dirs`:**
   Signatur bleibt rückwärts-kompatibel. Der zweite Aufruf-Pfad
   (programmatischer Caller ohne vorberechneten spec) muss weiter
   funktionieren. `resolve_watch_dirs(module, explicit_dirs, *,
   spec=None)` — wenn `spec is None`, wird selbst aufgelöst.

2. **E2E-Test mocked `os.execvpe`, nicht `os.kill`:**
   Der Test muss durch den echten SIGHUP-Handler durchlaufen
   (sonst ist es kein E2E), aber execvpe würde den Pytest-Prozess
   ersetzen. Mocken von `os.execvpe` auf Modul-Ebene
   (`swarmq.process_manager.os.execvpe`) ist der bestehende
   Pattern aus `TestReloadOrphanGuard`.

3. **Re-Entrancy-Test bleibt Unit-Scope (nicht Integration):**
   Signal-Handler-Installation + `os.kill(getpid(), SIGHUP)` ist
   selbst innerhalb pytest zuverlässig reproduzierbar. Kein
   echter `watchfiles.watch`-Aufruf nötig — wir fahren den
   `_on_reload_signal` direkt und beobachten `is_busy()`-Ausgabe.

4. **Wiring-Test verwendet `MagicMock` + `call_args.kwargs`:**
   Kein Refactor des Fakes; der existierende Mock-Ansatz deckt
   die neuen Assertions durch Inspektion der Call-Args ab.

## Implementation Units

- [ ] **Unit 1: spec-pass-through in resolve_watch_dirs**

**Goal:** `find_spec(args.module)` wird im Supervisor nur einmal
aufgerufen. `_validate_module_importable` gibt den spec zurück,
`run_multi_process_worker` reicht ihn an `resolve_watch_dirs` durch.

**Files:**
- Modify: `src/swarmq/process_manager.py`
  - `_validate_module_importable(module: str) -> ModuleSpec` —
    Return-Type ergänzen, spec zurückgeben.
  - `run_multi_process_worker` — `spec = _validate_module_importable(...)`,
    dann `resolve_watch_dirs(args.module, watch_dirs_raw, spec=spec)`.
- Modify: `src/swarmq/hot_reload.py`
  - `resolve_watch_dirs(module: str, explicit_dirs: Iterable[str],
    *, spec: ModuleSpec | None = None) -> tuple[str, ...]` —
    neuer keyword-only Parameter.
- Modify: `tests/unit/test_cli_multiprocess.py` — existierende
  Tests für `_validate_module_importable` ggf. anpassen, falls
  Return-Value assertet wird.
- Modify: `tests/unit/test_hot_reload.py::TestResolveWatchDirs` —
  zusätzlicher Test `test_explicit_spec_skips_find_spec`.

**Approach:**
```python
# process_manager.py
def _validate_module_importable(module: str) -> importlib.util.ModuleSpec:
    try:
        spec = importlib.util.find_spec(module)
    except (ImportError, ValueError) as exc:
        raise ConfigurationError(...) from exc
    if spec is None or spec.origin is None:
        raise ConfigurationError(...)
    return spec

# In run_multi_process_worker:
spec = _validate_module_importable(args.module)
...
if reload_enabled:
    ...
    resolved_watch_dirs = resolve_watch_dirs(
        args.module, watch_dirs_raw, spec=spec,
    )

# hot_reload.py
def resolve_watch_dirs(
    module: str,
    explicit_dirs: Iterable[str],
    *,
    spec: importlib.util.ModuleSpec | None = None,
) -> tuple[str, ...]:
    explicit = tuple(dict.fromkeys(explicit_dirs))
    if explicit:
        return explicit
    if spec is None:
        try:
            spec = importlib.util.find_spec(module)
        except (ImportError, ValueError) as exc:
            raise ConfigurationError(...) from exc
    if spec is None or spec.origin is None:
        raise ConfigurationError(...)
    # Rest unverändert.
```

**Test scenarios:**
- Positivpfad: Supervisor ruft `find_spec` genau einmal (via
  `unittest.mock.patch('importlib.util.find_spec')` mit Call-
  Counter-Verify).
- `resolve_watch_dirs("json", (), spec=<prebuilt>)` ruft
  `importlib.util.find_spec` **nicht** auf (Mock bestätigt).
- Programmatischer Caller ohne spec-kwarg funktioniert
  unverändert (Regression).

**Verification:** `pytest tests/unit/test_hot_reload.py::TestResolveWatchDirs tests/unit/test_process_manager.py -v`.

- [ ] **Unit 2: Wiring-Test härtet Kwarg-Identität**

**Goal:** `test_run_starts_and_stops_watcher` assertet dass das
echte Wiring von `ProcessManager.run()` die richtigen Callables
und Daten an `FileWatcher` übergibt. Eine falsche Closure oder
ein statisches Fake würde ab jetzt rot machen.

**Files:**
- Modify: `tests/unit/test_process_manager.py::TestFileWatcherIntegration::test_run_starts_and_stops_watcher`
  - Capture `FileWatcher.__init__`-Calls, inspect `call_args.kwargs`.
  - Neue Assertions: `watch_dirs == ("/tmp",)`, `callable(is_busy)`,
    `callable(trigger)`.
  - Runtime-Verifikation: `is_busy()` vor Signal → False, nach
    manuellem `pm._reload_requested = True` → True.
  - Runtime-Verifikation: `trigger` als Callable aufrufen mit
    gemocktem `os.kill` → erwartet `os.kill(os.getpid(), signal.SIGHUP)`.

**Approach:**
```python
def test_run_starts_and_stops_watcher(self):
    pm = self._pm(reload=True, watch_dirs=("/tmp",))
    fake_watcher = MagicMock()
    with patch.object(pm, "_start_all_workers"), \
         patch.object(pm, "_setup_signals"), \
         patch.object(pm, "_monitor_loop", return_value=0), \
         patch.object(pm, "_shutdown_all_workers"), \
         patch.object(pm, "_collect_zombies"), \
         patch(
             "swarmq.hot_reload.FileWatcher",
             return_value=fake_watcher,
         ) as FW_cls, \
         patch("swarmq.process_manager.os.kill") as mock_kill:
        pm.run()

    fake_watcher.start.assert_called_once()
    fake_watcher.stop.assert_called_once()

    # NEW: Kwarg identity.
    kwargs = FW_cls.call_args.kwargs
    assert kwargs["watch_dirs"] == ("/tmp",)
    is_busy = kwargs["is_busy"]
    trigger = kwargs["trigger"]
    assert callable(is_busy) and callable(trigger)

    # NEW: is_busy closure reads pm._reload_requested.
    pm._reload_requested = False
    assert is_busy() is False
    pm._reload_requested = True
    assert is_busy() is True

    # NEW: trigger fires SIGHUP at own PID.
    trigger()
    mock_kill.assert_called_once()
    (target_pid, target_sig), _ = mock_kill.call_args
    assert target_pid == os.getpid()
    assert target_sig == signal.SIGHUP
```

**Test scenarios:**
- Original happy-path erhält Regression-Guard.
- Closure-Regression-Test: wenn jemand `is_busy=lambda: False`
  fest verdrahtet, schlagen Assertions fehl.

**Verification:** `pytest tests/unit/test_process_manager.py::TestFileWatcherIntegration::test_run_starts_and_stops_watcher -v`.

- [ ] **Unit 3: End-to-End CLI → Watcher → SIGHUP → execvpe**

**Goal:** Ein Integration-Test, der das komplette Hot-Reload-
Happy-Path-Szenario durchspielt. Real ProcessManager, realer
FileWatcher, reales watchfiles, realer SIGHUP-Pfad, **gemocktes**
`os.execvpe` (letzter Schritt — würde sonst Pytest ersetzen).

**Files:**
- Add: `tests/integration/test_hot_reload_e2e.py::test_file_write_triggers_execvpe`

**Approach:**
```python
@pytest.mark.integration
def test_file_write_triggers_execvpe(tmp_path: Path) -> None:
    """Full chain: .py write → watcher → SIGHUP → supervisor → execvpe."""
    from swarmq.process_manager import ProcessManager

    pm = ProcessManager(
        num_workers=0,  # No real subprocesses — focus on supervisor
        worker_entry=lambda *a, **k: None,
        reload=True,
        watch_dirs=(str(tmp_path),),
    )
    # Make _monitor_loop observable but fast: loop until reload_requested.
    def short_monitor():
        import time
        deadline = time.monotonic() + 5.0
        while time.monotonic() < deadline:
            if pm._reload_requested:
                return 0
            time.sleep(0.05)
        return 0
    pm._monitor_loop = short_monitor

    execvpe_called = threading.Event()
    def fake_execvpe(*args, **kwargs):
        execvpe_called.set()
        # Return instead of replacing process.
        return None

    with patch("swarmq.process_manager.os.execvpe", side_effect=fake_execvpe), \
         patch.object(pm, "_start_all_workers"), \
         patch.object(pm, "_shutdown_all_workers"), \
         patch.object(pm, "_collect_zombies"):
        # Spawn pm.run() in a background thread so we can trigger
        # a file write while it is in monitor_loop.
        result_holder: dict = {}
        def run_pm():
            try:
                result_holder["rc"] = pm.run()
            except Exception as exc:
                result_holder["exc"] = exc
        t = threading.Thread(target=run_pm, daemon=True)
        t.start()

        # Let watcher arm.
        time.sleep(0.5)
        (tmp_path / "tasks.py").write_text("# reload me\n")

        # Give watcher debounce + trigger + signal dispatch headroom.
        assert execvpe_called.wait(timeout=5.0), (
            "execvpe not reached within 5s of file write"
        )
        t.join(timeout=2.0)

    assert pm._reload_requested is True
    assert "rc" in result_holder, f"pm.run() raised: {result_holder.get('exc')}"
```

**Test scenarios:**
- Happy path: File-Write landet in execvpe-Mock.
- Negativtest (optional — eher in Unit 4): keine File-Write →
  execvpe nie aufgerufen → Test-Timeout macht sichtbar dass
  Watcher nicht einfach "immer" triggert.

**Verification:** `pytest tests/integration/test_hot_reload_e2e.py::test_file_write_triggers_execvpe -v`.

**Caveat:** Der Test braucht echte `watchfiles`-Installation
(ist in `[reload]` Extra und in der Dev-Umgebung schon aktiv).
`pytest.importorskip("watchfiles")` als erste Zeile macht
CI-Runner ohne Extra toleranzfähig.

- [ ] **Unit 4: Re-Entrancy-Test mit realem SIGHUP**

**Goal:** Der bestehende `test_trigger_suppressed_when_busy`
validiert nur das `is_busy`-Contract-Verhalten mit einem
statischen Fake. Ein neuer Test instrumentiert den realen
Signal-Handler und belegt die Bindung `_on_reload_signal →
_reload_requested → is_busy-closure`.

**Files:**
- Add: `tests/unit/test_process_manager.py::TestReloadReentrancy`

**Approach:**
```python
class TestReloadReentrancy:
    """R5.3 ce-review #10: re-entrancy with real SIGHUP dispatch."""

    def test_real_sighup_sets_reload_requested_and_blocks_second_fire(self):
        pm = ProcessManager(
            num_workers=0, worker_entry=_entry_stub,
            reload=True, watch_dirs=("/tmp",),
        )
        # Install the real signal handler on the calling thread.
        pm._setup_signals()

        # Build the is_busy closure exactly as run() does.
        is_busy = lambda: pm._reload_requested

        # Before signal: not busy.
        assert is_busy() is False

        # Send real SIGHUP.
        os.kill(os.getpid(), signal.SIGHUP)

        # Give the signal dispatcher a tick. Synchronous on CPython
        # because signal handlers run on the main thread between
        # bytecodes — os.kill to self is processed before the next line.
        assert pm._reload_requested is True
        assert is_busy() is True  # closure reflects the update

    def test_second_sighup_while_busy_is_idempotent(self):
        pm = ProcessManager(
            num_workers=0, worker_entry=_entry_stub,
            reload=True, watch_dirs=("/tmp",),
        )
        pm._setup_signals()

        os.kill(os.getpid(), signal.SIGHUP)
        os.kill(os.getpid(), signal.SIGHUP)

        # Idempotent at flag level (may log twice — that's OK).
        assert pm._reload_requested is True
        assert pm._shutting_down is True
```

**Test scenarios:**
- `_setup_signals` installiert Handler korrekt auf dem Testing-
  Thread.
- Erster SIGHUP: `_reload_requested == True`.
- Zweiter SIGHUP while busy: bleibt `True`, kein Crash.
- is_busy-Closure reflektiert den Flag-Zustand (nicht gecachter
  Snapshot).

**Caveat:** Der Test installiert echte Signal-Handler auf der
Test-Runner-Prozess-Ebene. Die pytest-Session bleibt nach dem
Test stabil, aber andere Tests die SIGHUP abfangen würden, sind
beeinflusst. **Aufräumen via `pytest.fixture` mit
`signal.signal(SIGHUP, SIG_DFL)` im teardown.** Fixture
`restore_default_signal_handlers()` als autouse im Test-Scope.

**Verification:** `pytest tests/unit/test_process_manager.py::TestReloadReentrancy -v`.

## System-Wide Impact

- **Keine API-Breaking-Changes.** `resolve_watch_dirs` bekommt
  einen keyword-only Parameter mit Default — rückwärts-kompatibel.
  `_validate_module_importable` war bereits interne API,
  Return-Type-Erweiterung ist sicher.
- **Keine Broker/Backend/Schema-Änderung.**
- **Keine CLI-Änderung.**
- **Keine Logging-Änderung.**
- **Test-Count:** +3 bis +5 neue Tests (Unit 1: 1, Unit 2: 0
  neue, Modifikation existierender Test; Unit 3: 1; Unit 4: 2).
- **Laufzeit:** Unit 3 ist der teuerste — ~1.5-2.5s wegen
  watchfiles-arm-Delay + debounce. Liegt im Integration-Marker,
  wird im Dev-Loop nicht gelaufen.

## Risks & Dependencies

| Risk | Mitigation |
|------|------------|
| Unit 3 E2E ist zeit-sensitiv auf geladener CI | `@pytest.mark.integration` Marker; `execvpe_called.wait(timeout=5.0)` ist großzügig. Kein CI-Jitter-Risiko wenn Runner >=1 CPU hat. |
| Unit 4 installiert globale Signal-Handler auf Test-Runner | Autouse-Fixture stellt SIG_DFL im teardown wieder her. Isolation-Test vor der Fixture-Änderung verifizieren. |
| Unit 1 ändert `_validate_module_importable`-Signatur | Interne Funktion, nur ein Caller (`run_multi_process_worker`) + Test. Kein Downstream-Code betroffen. |
| `resolve_watch_dirs`-Signatur-Erweiterung | Keyword-only, default None → bestehende Aufrufer unverändert. Mypy prüft Call-Sites. |
| `os.execvpe` Mock kann in Unit 3 nicht alle Code-Pfade erfassen | Der Mock deckt den "execvpe wurde aufgerufen"-Kontrakt ab, nicht was execvpe macht (Prozess-Replacement). Das ist bewusst — execvpe zu testen ist OS-Kontrakt, nicht unser Scope. |
