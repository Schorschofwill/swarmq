## Overview

Automatischer Trigger für den bereits existierenden SIGHUP-Reload-Pfad.
Ein `watchfiles`-basierter Daemon-Thread beobachtet das Task-Modul-
Verzeichnis und sendet bei relevanten Änderungen `SIGHUP` an den
Supervisor-Prozess. Die gesamte Reload-Mechanik (Kinder killen,
argv-Snapshot, `os.execvpe`, Orphan-Guard) läuft unverändert — R5.3
liefert nur den neuen Trigger.

**Nicht-Ziele:** Keine neue Reload-Semantik, keine Änderung am
bestehenden SIGHUP-Handler, keine Watcher im Worker-Subprozess. Hot
Reload bleibt Developer-Feature (Production-WARN-Log).

## Problem Frame

1. **Kein automatischer Reload:** Manueller `kill -HUP <pid>` ist der
   einzige Weg, Task-Code-Änderungen zu aktivieren. Im Development-
   Flow bricht das die iterative Schleife — Entwickler vergessen es
   oder killen stattdessen den ganzen Worker.

2. **Supervisor ist synchron:** `ProcessManager.run()` läuft ohne
   asyncio-Loop (`time.sleep(0.5)` im `_monitor_loop`). Die
   `watchfiles`-async-API (`awatch`) passt nicht natürlich — die
   sync-API (`watch`) in einem Daemon-Thread ist die idiomatische
   Einbettung.

3. **Watch-Scope ist ein Bikeshed-Risiko:** CWD ist zu breit (liest
   `site-packages`-Watches auf macOS/Windows durch die inotify-Kette),
   `sys.path` ist zu breit (virtualenv, Standard-Library). Task-Modul-
   Parent-Directory ist der schmalste sinnvolle Default.

4. **Reload-Storms aus Editor-Noise:** `4913`-Probe-Files (Vim),
   `.sw[px]`, `~$`-Backups, `format-on-save`-Bursts erzeugen
   Änderungsevents, die ohne Filter + Debounce die Reload-Pipeline
   überfluten.

5. **Reentrancy während Reload:** Kommt ein File-Change während
   `_shutdown_all_workers` läuft (der Supervisor hat `shutdown_event`
   gesetzt, Kinder drainen), darf **kein** zweites SIGHUP gefeuert
   werden — der Handler ist nicht idempotent (setzt Flags neu, logged
   ein zweites `process_manager_reload_requested`).

## Scope Boundaries

**In Scope:**
- `src/swarmq/hot_reload.py` — neues Modul mit `_FileWatcher`, `SwarmQFilter`, Watch-Root-Resolution.
- `src/swarmq/cli.py` — `--reload`, `--watch-dir` flags (argparse).
- `src/swarmq/process_manager.py` — `WorkerConfig`-Erweiterung, Integration in `ProcessManager.run()`.
- `pyproject.toml` — `[project.optional-dependencies]` Extra `reload = ["watchfiles>=0.21"]`.
- Unit- + Integration-Tests.
- `website/docs/guides/hot-reload.md` + CLI-Reference-Update.

**Out of Scope (bewusst):**
- Async-Watcher (`awatch`) — Supervisor ist synchron, der Thread-Approach ist einfacher und korrekt.
- Watch des Frameworks selbst (`src/swarmq/**`) — nur User-Task-Modul, damit Framework-Änderungen nicht zu endlosen Reload-Schleifen bei `pip install -e .` führen.
- Production-Safety-Rails (z.B. Block mit `SWARMQ_ENV=production`). Nur Warning, kein Enforcement — Operator-Responsibility.
- Reload-on-Config-Change (`.env`, `swarmq.yaml`). Nur `.py`-Files. Config-Changes sind Worker-Restart, nicht Reload.
- Web-Server-Reload-Delay / Child-Worker-Warmup-Signal. Reload ist exakt das, was `os.execvpe` ohnehin tut.

## Key Decisions

1. **Optional-Dep via Extra `[reload]`:**
   `pip install swarmq[reload]` statt default-Dep. watchfiles bringt
   ein Rust-Wheel (~1 MB) mit — Core-User ohne Reload-Bedarf zahlen
   diesen Footprint nicht. Fehlt die Dep bei `--reload` → Fail-Fast
   mit `ConfigurationError` und konkreter Install-Anweisung.

2. **Re-Entrancy-Policy = skip:**
   Wenn `self._reload_requested` bereits `True` ist, wird der
   Change ignoriert (`logger.debug("reload_skip_reentrant", ...)`).
   Keine Queue, kein Defer — der laufende Reload bringt die
   Änderung ohnehin mit (fresher Subprocess-Start re-importiert
   alles). Simplexer als Queue-basiertes Defer und ohne Gefahr
   eines Reload-Regens.

3. **Watch-Thread-Crash = Supervisor bleibt stehen (mit Warning):**
   Reload ist Developer-Feature. Ein kaputter Watcher (Permission-
   Error auf einer watched path, inotify-exhaustion, Rust-Panic)
   darf keinen produktiven Worker-Supervisor killen. Thread-Top-
   Level-`except Exception`, WARNING-Log, Thread endet sauber.

4. **Default-Watch-Root via `find_spec(module).origin`-Parent:**
   Nutzt den bereits existierenden `_validate_module_importable`-
   Pfad aus R4.6-Hardening. `spec.origin` ist bei Top-Level-Modulen
   der Pfad zu `my_module.py` (→ parent = project root); bei
   Packages der Pfad zu `my_package/__init__.py` (→ parent =
   `my_package/`). Ohne `--watch-dir`-Override kein CWD-Fallback.

5. **WARNING-Log obligatorisch:**
   Beim Start mit `--reload` wird einmalig `hot_reload_enabled`
   mit WARNING ausgegeben — analog `uvicorn --reload`. Operator
   soll dreimal hinsehen, wenn das Log in Production auftaucht.

6. **`watchfiles.watch()` (sync) statt `awatch` (async):**
   Der Supervisor hat **keinen** asyncio-Loop (R4.6-Befund:
   `_monitor_loop` ist `time.sleep(0.5)`). Sync-API in Daemon-
   Thread ist die natürliche Integration. Stop-Mechanismus:
   `threading.Event` als `stop_event` an `watch(..., stop_event=...)`.

7. **Filter: `PythonFilter`-Subklasse:**
   Built-in `PythonFilter` erschlägt `__pycache__/.git/.venv/*.pyc/*.swp/~$`.
   Wir subklassen nur für `4913` (Vim-Probe-File, kein Extension-
   Match), `.tmp` und `*.bak`. Keine eigene Regex-Maschine.

```python
def _watch_dir_path(value: str) -> str:
    p = Path(value)

        raise argparse.ArgumentTypeError(
```

- [ ] **Unit 3: `hot_reload.py` — `_FileWatcher` (Thread + SIGHUP)**

**Goal:** Neues Modul `src/swarmq/hot_reload.py` kapselt die komplette

**Files:**

**Approach:**
```python
"""File-watch-based SIGHUP trigger for hot reload.

Imported lazily by process_manager.run() so that `watchfiles` stays
an optional dependency.
"""
from __future__ import annotations

import threading
from collections.abc import Callable, Iterable
from typing import TYPE_CHECKING

import structlog

if TYPE_CHECKING:
    from watchfiles import BaseFilter  # type-only import

logger = structlog.get_logger()


class FileWatcher:
    def __init__(
        self,
        watch_dirs: Iterable[str],
        trigger: Callable[[], None],
        is_busy: Callable[[], bool],
        file_filter: "BaseFilter | None" = None,
        # Keep knobs testable — default to watchfiles' own sane defaults.
        debounce_ms: int = 1600,
        step_ms: int = 50,
    ) -> None:
        self._dirs = tuple(watch_dirs)
        self._trigger = trigger
        self._is_busy = is_busy
        self._filter = file_filter  # None → resolved in _run
        self._debounce_ms = debounce_ms
        self._step_ms = step_ms
        self._stop_event = threading.Event()
        self._thread: threading.Thread | None = None

    def start(self) -> None:
        if self._thread is not None:
            raise RuntimeError("FileWatcher already started")
        self._thread = threading.Thread(
            target=self._run,
            name="swarmq-file-watcher",
            daemon=True,
        )
        self._thread.start()
        logger.info(
            "watch_started",
            watch_dirs=list(self._dirs),
            debounce_ms=self._debounce_ms,
        )

    def stop(self, timeout: float = 2.0) -> None:
        self._stop_event.set()
        if self._thread is not None and self._thread.is_alive():
            self._thread.join(timeout=timeout)
        logger.info("watch_stopped")

    def _run(self) -> None:
        # Lazy import: watchfiles is optional.
        try:
            from watchfiles import watch

            file_filter = self._filter or _default_filter()
        except ImportError:  # pragma: no cover — guarded at start-time
            logger.error("watchfiles_import_failed")
            return
        try:
            for changes in watch(
                *self._dirs,
                stop_event=self._stop_event,
                watch_filter=file_filter,
                debounce=self._debounce_ms,
                step=self._step_ms,
                rust_timeout=1000,  # yield every 1s even if quiet
            ):
                if self._stop_event.is_set():
                    return
                if self._is_busy():
                    logger.debug(
                        "reload_skip_reentrant",
                        changed_count=len(changes),
                    )
                    continue
                logger.info(
                    "reload_triggered",
                    changed_count=len(changes),
                    # Cap preview to avoid log-bloat on git-checkout:
                    changed_sample=[p for _, p in list(changes)[:5]],
                )
                try:
                    self._trigger()
                except Exception:
                    logger.exception("reload_trigger_failed")
        except Exception:
            # R-6: watcher crash must not take down the supervisor.
            logger.warning("watch_thread_crashed", exc_info=True)


def _default_filter() -> "BaseFilter":
    from watchfiles import PythonFilter

    class SwarmQFilter(PythonFilter):
        _IGNORED_BASENAMES = frozenset({"4913"})
        _IGNORED_SUFFIXES = (".tmp", ".bak")

        def __call__(self, change, path: str) -> bool:
            basename = path.rsplit("/", 1)[-1]
            if basename in self._IGNORED_BASENAMES:
                return False
            if path.endswith(self._IGNORED_SUFFIXES):
                return False
            return super().__call__(change, path)

    return SwarmQFilter()


def check_watchfiles_available() -> None:
    """Raise ConfigurationError if `watchfiles` is not installed.

    Called from `run_multi_process_worker` before the supervisor starts,
    so missing-dep fails fast with a clear install hint.
    """
    try:
        import watchfiles  # noqa: F401
    except ImportError as exc:
        from swarmq.exceptions import ConfigurationError

        raise ConfigurationError(
            "--reload requires the optional 'watchfiles' dependency. "
            "Install with:  pip install 'swarmq[reload]'"
        ) from exc
```

```python
def resolve_watch_dirs(
    module: str, explicit_dirs: Iterable[str]
) -> tuple[str, ...]:
    """Return the final list of directories to watch.

    - If ``explicit_dirs`` is non-empty, use it verbatim (operator knows best).
    - Otherwise resolve ``module`` via ``importlib.util.find_spec`` and
      return the parent directory of ``spec.origin``.
    - Namespace-packages (``spec.origin is None``) raise
      ``ConfigurationError`` — user must pass ``--watch-dir``.
    """
    explicit = tuple(explicit_dirs)
    if explicit:
        return explicit
    import importlib.util
    from pathlib import Path
    from swarmq.exceptions import ConfigurationError

    spec = importlib.util.find_spec(module)
    if spec is None or spec.origin is None:
        raise ConfigurationError(
            f"--reload: cannot auto-detect watch directory for module "
            f"{module!r} (namespace package or missing origin). "
            f"Pass --watch-dir explicitly."
        )
    return (str(Path(spec.origin).parent),)
```

**Test scenarios:**
- `resolve_watch_dirs("os", ())` → tuple with parent of `os.py`'s path.
- `resolve_watch_dirs("nonexistent.xyz", ())` → `ConfigurationError`.
- `resolve_watch_dirs("os", ("/tmp",))` → `("/tmp",)` (explicit wins).
- `resolve_watch_dirs("os", ("/tmp", "/var"))` → both preserved, order-stable.

**Verification:** deterministisch, nutzt Standard-Library-Module für Positivpfad.

```python
import threading
import time
from pathlib import Path

import pytest

from swarmq.hot_reload import FileWatcher


@pytest.mark.integration
def test_file_write_triggers_callback(tmp_path: Path) -> None:
    triggered = threading.Event()
    watcher = FileWatcher(
        watch_dirs=(str(tmp_path),),
        trigger=triggered.set,
        is_busy=lambda: False,
        debounce_ms=200,  # shorter for test speed
        step_ms=50,
    )
    watcher.start()
    try:
        # Give the Rust watcher ~200ms to arm before first write.
        time.sleep(0.3)
        (tmp_path / "task.py").write_text("# new task")
        assert triggered.wait(timeout=3.0), "trigger not fired within 3s"
    finally:
        watcher.stop(timeout=2.0)
```

**Test scenarios:**
- Happy path: `.py`-Write triggert.
- Negativtest: `.pyc`-Write triggert nicht (`triggered.wait(1.0)` ist False).
- Negativtest: `4913`-Touch triggert nicht.

**Verification:** `pytest tests/integration/test_hot_reload_e2e.py -v`.
Marker `integration` damit optional skippable auf langsamen CI-Runnern.

## System-Wide Impact

- **Keine Broker/Backend-Schema-Änderung.**
- **Keine CLI-Breaking-Changes:** `--reload` und `--watch-dir` sind
  additiv.
- **Keine API-Breaking-Changes:** `ProcessManager.__init__` bekommt
  zwei keyword-only Parameter mit Defaults — rückwärtskompatibel.
- **WorkerConfig-Erweiterung:** zwei neue Felder mit Defaults —
  rückwärtskompatibel (pickle-Roundtrip mit Defaults bleibt stabil,
  sofern niemand `WorkerConfig(**old_dict)` mit älterer Dataclass-
  Definition aufruft; das tut niemand außer Tests).
- **Subprocess-Signatur:** unverändert — Watcher lebt im Supervisor.
- **Logging:** 4 neue Event-Namen (`watch_started`, `watch_stopped`,
  `reload_triggered`, `reload_skip_reentrant`, `watch_thread_crashed`,
  `hot_reload_enabled`, `watch_dir_ignored_without_reload`, `watchfiles_import_failed`)
  — alle konsistent mit snake_case-Convention.

## Risks & Dependencies

| Risk | Mitigation |
|------|------------|
| `watchfiles` Rust-Wheel bricht auf exotischer Plattform | Optional-Dep — Core-User nicht betroffen. Install-Fehler ist sichtbar (wheel-download scheitert). |
| inotify-Exhaustion auf Linux (default 8192 watches) | Watch-Root ist auf Task-Modul-Parent beschränkt (R-3). Guide erwähnt `sysctl fs.inotify.max_user_watches`. |
| `find_spec(args.module).origin` ist `None` bei Namespace-Packages | `resolve_watch_dirs` raist `ConfigurationError` mit Hinweis auf `--watch-dir` (Unit 5). |
| Reload-Schleife wenn User-Code sein eigenes Modul mutiert (z.B. auto-generierte Artifacts im watched dir) | PythonFilter schließt `__pycache__` aus. User-gen `.py`-Files sind User-Verantwortung — Guide-Troubleshooting-Section. |
| Thread-Crash wird unbemerkt (Watcher weg, Supervisor weiter) | WARNING-Log + Guide-Erwähnung. Healthcheck-Integration ist Follow-Up wenn Bedarf auftaucht. |
| `os.kill(getpid(), SIGHUP)` könnte eine Race mit `_setup_signals` verlieren, wenn der Watcher vor dem Signal-Handler-Install startet | Unit 6 startet den Watcher **nach** `_setup_signals()` — dokumentiert im Code-Kommentar. |
| `watchfiles.watch()` in einem Daemon-Thread hält Python beim Shutdown nicht auf, kann aber den `stop_event` verpassen wenn Supervisor abrupt stirbt | Daemon-Thread + `stop_event.set()` im `finally` — ausreichend für ordentlichen Shutdown; bei abruptem Kill ist der Watcher-Zustand egal. |
| `--watch-dir` akzeptiert Pfade außerhalb des Projekts → User kann `/etc` watchen | Guide-Warnung. Kein technisches Enforcement — der Operator ist authoritative. |
