Getting Started

From a fresh virtualenv to a running worker processing tasks in under five minutes. No entrypoint boilerplate, no config files required.

Prerequisites

SwarmQ needs a RabbitMQ broker and a Valkey (or Redis) backend. The repository ships a docker-compose.yml that brings both up locally.

  • Python 3.11+ (3.14 supported, tested on CI)
  • Docker or a running RabbitMQ + Valkey pair
  • A package manager — examples use uv

Install

uv add swarmq
uv run swarmq --version
Note SwarmQ pulls aio-pika, valkey, and msgpack as direct dependencies. The library is pure Python — no C extensions to build.

Start the broker

Clone the repo (or copy the compose file) and bring the stack up. Both services expose default ports; the compose file includes healthchecks so workers wait for them to be ready.

shell 
docker compose up -d
docker compose ps

Define your first task

Tasks are Python classes that inherit from Task and declare their identity through a TaskInfo descriptor. The body lives in an async def run(...) method.

myapp/tasks.py 
from swarmq.task import Task, TaskInfo


class Greet(Task):
    # Identity, queue routing, and limits live here.
    task_info = TaskInfo(
        name="greet",
        queues=["default"],
        max_retries=2,
    )

    async def run(self, who: str) -> str:
        return f"hello, {who}"

Run a worker

No entrypoint file, no celery -A app worker-style wrapper. Point the CLI at your task module and start consuming.

shell 
export SWARMQ_BROKER_URL="amqp://guest:guest@localhost:5672/"
export SWARMQ_BACKEND_URL="valkey://localhost:6379/0"

swarmq worker --module myapp.tasks --queues default --concurrency 10
Tip For JSON logs fit for Loki, Datadog, or CloudWatch, add --log-format json. The process handles SIGTERM and SIGINT with a graceful drain.

Enqueue from your app

On the client side, instantiate a SwarmQ app with the same broker and backend URLs, then call schedule() on a task class.

enqueue.py 
import asyncio
from swarmq import SwarmQ
from myapp.tasks import Greet


async def main():
    app = SwarmQ(
        broker_url="amqp://guest:guest@localhost:5672/",
        backend_url="valkey://localhost:6379/0",
    )
    async with app:
        handle = await app.schedule(Greet, who="world")
        result = await handle.wait(timeout=10)
        print(result)  # "hello, world"


asyncio.run(main())
Heads up The async with block manages both broker connection and backend pool. Forgetting it leaks AMQP channels and keeps Valkey connections open until GC.
