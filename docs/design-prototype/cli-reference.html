CLI Reference

The swarmq binary is the primary way to operate SwarmQ in production. Every subcommand reads from SWARMQ_* environment variables by default; explicit flags always win.

swarmq worker

Start a worker process that consumes one or more queues.

swarmq worker --module <dotted.path> [--queues <q1,q2>] [--concurrency N] [--log-format human|json]

Flags

FlagDefaultDescription
--modulerequiredDotted Python path where task classes are defined.
--queuesdefaultComma-separated queue list. Order defines priority.
--concurrency10Maximum parallel task executions.
--log-levelINFODEBUG / INFO / WARNING / ERROR.
--log-formathumanhuman for TTY, json for aggregators.
--check—Validate connectivity and task registration, then exit.

Example

shell 
swarmq worker \
  --module myapp.tasks \
  --queues priority,default,low \
  --concurrency 25 \
  --log-format json
Tip Use swarmq worker --check in container healthchecks — it exits 0 if broker + backend are reachable and the task module imports cleanly.

swarmq schedule

One-off CLI enqueue — useful for cron, debugging, or bootstrapping.

swarmq schedule <task_name> [--arg key=value]... [--delay SECONDS]

Example

shell 
swarmq schedule send_email \
  --arg to=alice@example.com \
  --arg subject=Welcome \
  --delay 60

swarmq dlq

Inspect and manipulate dead-letter queues.

swarmq dlq (list | requeue <message_id> | purge <queue>)
Destructive purge removes every message in the target queue and cannot be undone. Prefer requeue for recoverable failures.

swarmq inspect

Discover registered tasks, their queues, and rate limits from a task module.

shell 
$ swarmq inspect --module myapp.tasks

  name              queues          rate_limit    max_retries
  ──────────────────────────────────────────────────────────
  send_email        default,mail    100/m         3
  render_invoice    pdf             —             5
  ingest_webhook    ingress,default 50/s          2

3 task(s) registered.

swarmq version

Print the installed version and exit.

shell 
$ swarmq version
SwarmQ 0.3.0 (Python 3.14.0, aio-pika 9.5.1, valkey 6.1.0)
