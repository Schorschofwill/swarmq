usage: swarmq worker [-h] --module DOTTED.PATH [--configure MODULE:CALLABLE]
                     [--queues A,B,C] [--concurrency N] [--pool {io,cpu}]
                     [--log-level {DEBUG,INFO,WARNING,ERROR,CRITICAL}]
                     [--log-format {human,json}] [--log-config PATH]
                     [--no-configure-logging] [--logger-level NAME=LEVEL]
                     [--log-queue-size N] [--log-drain-timeout SECONDS]
                     [--log-lifecycle-level {DEBUG,INFO,WARNING,ERROR,CRITICAL}]
                     [--burst] [--metrics-port PORT] [--health-port PORT]
                     [--priorities] [--processes N] [--autoscale MIN,MAX]
                     [--max-processes N] [--group LABEL] [--reload]
                     [--watch-dir PATH] [--check]
                     [--burst-idle-timeout SECONDS]

Import a Python module so its Task subclasses register, then connect to broker
+ backend and consume. Broker and backend URLs come from SWARMQ_BROKER_URL and
SWARMQ_BACKEND_URL environment variables. Note: importing the module runs its
top-level code — this is the standard Python convention.

options:
  -h, --help            show this help message and exit
  --module DOTTED.PATH  Python module containing Task subclasses to register,
                        e.g. 'myapp.tasks'. Must be importable from the
                        current Python path.
  --configure MODULE:CALLABLE
                        Callable invoked with the SwarmQ app after
                        construction and before the worker starts, e.g.
                        'myapp.hooks:setup'. Use it to register middleware and
                        signal handlers without writing your own worker entry
                        point. Runs once per worker process; an awaitable
                        return value is awaited.
  --queues A,B,C        Comma-separated queue names to consume from (default:
                        default).
  --concurrency N       Maximum tasks executed in parallel (default: 10). With
                        --pool cpu this is the number of compute slots; the
                        default is then the number of CPUs assigned to the
                        worker (affinity and cgroup quota), divided by
                        --processes.
  --pool {io,cpu}       Execution pool (default: io). 'cpu' runs every task
                        body in a compute child forked from a pre-warmed
                        forkserver: the loop process never computes,
                        hard_timeout and cancel kill the child, --concurrency
                        means compute slots. POSIX only; not combinable with
                        --autoscale.
  --log-level {DEBUG,INFO,WARNING,ERROR,CRITICAL}
                        Log verbosity (default: INFO). DEBUG also surfaces
                        full tracebacks on CLI errors. Overrides
                        SWARMQ_LOG_LEVEL.
  --log-format {human,json}
                        Log output format (default: human). 'json' for
                        agent/log-aggregator consumption. Overrides
                        SWARMQ_LOG_FORMAT (and its alias SWARMQ_LOG_JSON).
  --log-config PATH     Logging dictConfig file (JSON; YAML with PyYAML
                        installed) applied in every swarmq process instead of
                        the built-in setup. Not combinable with --log-format
                        or --no-configure-logging. Overrides
                        SWARMQ_LOG_CONFIG.
  --no-configure-logging
                        Do not set up logging in any swarmq process. Overrides
                        SWARMQ_CONFIGURE_LOGGING.
  --logger-level NAME=LEVEL
                        Level for one logger, e.g. aio_pika=WARNING
                        (repeatable). Overrides SWARMQ_LOGGER_LEVELS (comma-
                        separated NAME=LEVEL).
  --log-queue-size N    Capacity of the in-process log queue (default: 10000).
                        Overrides SWARMQ_LOG_QUEUE_SIZE.
  --log-drain-timeout SECONDS
                        Upper bound for flushing the log queues at exit,
                        before a reload and before each compute result
                        (default: 5). Records not written in time are counted
                        as dropped. Overrides SWARMQ_LOG_DRAIN_TIMEOUT.
  --log-lifecycle-level {DEBUG,INFO,WARNING,ERROR,CRITICAL}
                        Level of the task_received/task_started lifecycle
                        events (default: DEBUG). Overrides
                        SWARMQ_LOG_LIFECYCLE_LEVEL.
  --burst               Burst mode (R4.5): exit cleanly once all configured
                        queues have been idle for --burst-idle-timeout
                        seconds. Useful for batch / cron-style deployments
                        where a worker should drain and exit rather than long-
                        poll forever.
  --metrics-port PORT   R5.1: serve Prometheus /metrics on the given port.
                        Auto-wires the signal-based collectors (task_total,
                        retries_total, etc.). Requires 'pip install
                        swarmq[metrics]'. Default bind: 127.0.0.1.
  --health-port PORT    R5.2: serve /health + /ready on the given port. /ready
                        pings broker + backend (2s timeout) and returns
                        structured JSON. Default bind: 127.0.0.1.
  --priorities          R4.3: auto-declare + consume the high/normal/low
                        triplet for every --queues base queue, so tasks with
                        TaskInfo(priority='high'|'low') route correctly.
                        Without this flag, publishing priority-tagged tasks
                        raises UnroutableMessage (no {queue}.high/.low
                        exists).
  --processes, -p N     R4.6: run N worker subprocesses under a supervisor
                        (ProcessManager). Default 1 still runs under the
                        supervisor. Subprocesses use multiprocessing spawn —
                        fresh broker/backend connections per worker. The
                        supervisor auto-restarts crashed workers (max 5
                        restarts per hour), and reloads on SIGHUP via
                        os.execvpe() with the startup sys.orig_argv snapshot.
  --autoscale MIN,MAX   R4.7: enable autoscaling between MIN..MAX workers
                        based on queue depth. Scale-up when pending tasks
                        exceed 50 * active workers; scale-down after 60s of
                        sustained idle. 30s cooldown between decisions.
                        Implies --processes (the initial count is clamped into
                        [MIN,MAX]).
  --max-processes N     Enable the control channel and declare the headroom: a
                        setpoint stored in the backend
                        ([<namespace>:]sq:control:setpoint:<group>) may raise
                        this supervisor to at most N worker processes. Slot
                        table, observability port ranges and the default
                        compute slots per worker are sized from N at start-up;
                        N must be at least --processes and the --autoscale
                        upper bound. Without this flag the supervisor never
                        reads or writes setpoints.
  --group LABEL         Group label for the control channel. Supervisors
                        sharing a label (and a backend) follow the same
                        setpoint, each on its own. Default: the sorted set of
                        --queues.
  --reload              R5.3: watch task modules for changes and trigger the
                        existing SIGHUP reload pipeline (supervisor re-exec).
                        Implies --processes. Developer-only — do not use in
                        production. Requires 'pip install "swarmq[reload]"'.
                        Missing 'watchfiles' exits with code 78 (1 under
                        --check); invalid --watch-dir exits 2.
  --watch-dir PATH      R5.3: directory to watch (repeatable). Without this
                        flag, the parent directory of --module's resolved
                        source file is used. Ignored without --reload (a
                        WARNING is logged).
  --check               Dry-run validation mode. Verify --module is
                        importable, (with --reload) that 'watchfiles' is
                        installed + watch-dirs resolve, that the --metrics-
                        port/--health-port ranges across all worker processes
                        stay <= 65535 and do not overlap, the logging settings
                        and --log-config (dictConfig probe), pool constraints
                        (--pool cpu with --autoscale) and the --max-processes
                        headroom. Prints a JSON summary to stdout, exits 0 on
                        success or 1 on any validation error. Does NOT connect
                        to broker or backend.
  --burst-idle-timeout SECONDS
                        Seconds of queue silence required before --burst exits
                        (default: 5.0). The idle clock starts at worker-ready
                        and resets on every delivered message. Ignored without
                        --burst. Exit code 0 on clean drain (indistinguishable
                        from SIGTERM; grep logs for 'burst_idle_exit' to
                        distinguish).
